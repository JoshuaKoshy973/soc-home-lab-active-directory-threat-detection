# Incident Report: Failed Windows Logon Activity

## Summary

Failed Windows logon activity was simulated and detected in Splunk using Windows Security Event ID 4625. Failed logon events are common in enterprise environments, but repeated failures can indicate password guessing, brute-force attempts, misconfigured services, expired credentials, or suspicious authentication activity.

The activity was generated by attempting to log in with incorrect credentials and was detected through Windows Security logs ingested into Splunk.

## Environment

* Host: `WIN-CLIENT-01` and/or `DC-01`
* Domain: `soclab.local`
* Log Source: `WinEventLog:Security`
* SIEM: Splunk Enterprise
* Detection Type: Failed authentication monitoring

## Detection Logic

```spl
index=* source="WinEventLog:Security" EventCode=4625
| table _time host source sourcetype EventCode
```

## Relevant Windows Event ID

* Event ID 4625: An account failed to log on

## MITRE ATT&CK Mapping

* Tactic: Credential Access
* Technique: Brute Force — T1110
* Sub-technique: Password Guessing — T1110.001
* Tactic: Initial Access
* Related Technique: Valid Accounts — T1078

## Evidence

The Splunk search returned Windows Security events showing failed logon attempts. These events were identified by Event ID 4625 and showed that authentication attempts failed against Windows systems in the lab environment.

## Analysis

The failed logon activity was intentionally generated for lab testing. In a real SOC environment, failed logons must be reviewed in context. A small number of failed logons may be normal user error, but repeated failures from the same source, against multiple accounts, or followed by a successful logon may indicate suspicious activity.

Failed logon events are especially important when they involve:

* Multiple failures against the same account
* Multiple accounts targeted from the same source
* Failed logons followed by a successful logon
* Attempts against privileged accounts
* Logons from unusual hosts or source IP addresses
* Activity outside normal business hours

In this lab, the detection confirmed that Windows failed authentication events were being collected and could be searched in Splunk.

## Severity

Low to Medium

A small number of failed logons may be low severity if caused by normal user error. Repeated failed logons, especially against privileged accounts or from unusual sources, should be treated as medium or high severity depending on the pattern.

## Recommended Response

1. Identify the account involved in the failed logon attempts.
2. Review the source host or source IP address.
3. Determine whether the failed attempts were user error or suspicious activity.
4. Check whether a successful logon occurred after the failures.
5. Review whether the targeted account is privileged or sensitive.
6. If brute-force activity is suspected, disable or lock the affected account if necessary.
7. Reset the account password if compromise is suspected.
8. Review additional authentication logs for related activity.

## Conclusion

This simulated incident demonstrated how Windows Security Event ID 4625 can be used to detect failed authentication activity in Splunk. Monitoring failed logons is a core SOC use case because it helps identify password guessing, brute-force attempts, and suspicious authentication behavior.
